# TTMall 聊天订单查询与绑定迭代方案

## 范围

只对 `parseTtmallProductSource` 判定为 TTMall 的站点生效。Shopify、普通聊天、商品卡和现有绑定入口保持原逻辑。

## 实施

1. 新增 `server/chat-order-intent-service.js`：提取独立 16 位订单号；对订单状态、追踪、到货和“我的订单”语义做保守识别，并排除通用物流政策、退换货和破损售后。识别前先解析站点类型，非 TTMall 直接返回空。
2. 在访客与登录聊天回复生成前插入确定性 `order_action` 消息，携带状态、站点和订单号，不进入知识库或长期记忆提取；访客提示登录，已登录提示绑定。
3. 消息存储层映射 `orderAction`，前端复用反馈行动气泡样式和现有 TTMall 绑定面板；按钮不直接读取外部订单，绑定完成后再通过现有 profile order service 查询。
4. 记录更新日志、Bug 状态和针对性自检；不迁移数据库，不改 Shopify 分支。

## 验收

- 中文、英语、西语同义订单请求与 16 位订单号可触发；普通 shipping policy、破损售后、tracking 长串不触发。
- 非 TTMall 站点不生成行动消息；同一消息幂等，不重复插入。
- 游客得到登录提示，已登录未绑定得到绑定提示；已有绑定面板、订单接口和商品/图片/语音链路无回归。
- 完成本地模块测试、消息映射检查和本地 HTTP 健康检查。
