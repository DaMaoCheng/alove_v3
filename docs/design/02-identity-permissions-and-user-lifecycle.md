# 02. 身份、权限与用户生命周期

## 当前身份与权限

| 身份 | 核心权限 | 状态 |
| --- | --- | --- |
| 未认证访问者 | 在已启用站点可公开浏览并使用受限前台游客聊天；其他写操作需要认证。 | Current |
| Personal user | 在所属站点聊天、使用可见角色、维护资料、创建普通角色。 | Current |
| Creator | 具备 Personal 权限，可创建并使用一个受站点约束的 Creator 角色；用户侧编辑、删除等完整管理能力尚未实现。 | Current |
| Admin | 管理站点、角色、前台、活动、知识库、账号和日志。 | Current |

`Current`：游客使用独立受限 guest session 和 HttpOnly cookie，不创建或污染 `users` 记录；能力由站点级 `guest_chat_enabled` 控制，默认关闭。

`Current`：管理员可在账号管理中审计游客会话数量、有效状态、站点、前台角色、滚动消息额度、语音输入、附件、通话用量、自拍资格、认证承接结果和游客阶段对话；该只读能力不把游客伪装成正式账号，也不暴露游客认证凭证。

`Current`：普通用户、创作者和管理员的权限由服务端账号类型与站点归属控制；前端隐藏入口不能替代服务端授权。

`Current local UI`：Creator 账号首页侧栏已开放个人看板入口，页面身份信息读取当前账号，并提供 7/30/90 天、会话、商品触发、独立站跳转、跳转率和单指标趋势的承载结构；真实 analytics service/API 尚未实现，因此当前不展示演示数字。该本地状态尚未发布。

`Approved direction`：Creator analytics 必须按当前登录 owner 和可信消息/会话/角色关系统计；Creator 还应具备用户侧角色编辑、删除和完整工作区管理能力。UI 入口不能替代服务端 owner scope 与站点隔离。

## 游客生命周期

`Current`：游客在 session 冻结的当前站点内可激活并使用所有公开、已发布且本站可见的角色；角色创建仍必须认证。每个角色拥有独立的文字、语音输入、附件消息和实时通话用户转写 30 条/滚动 24 小时额度；文字、语音输入和附件另受每角色 10 条/10 分钟服务端限速，实时通话不受该短时限速。每个角色第 20 条后显示软注册提示，第 30 条回复完成后结束该角色通话或停止该角色发送并要求登录/注册。

`Current`：游客可成功生成一次图片、浏览只读 Kitshop 并接收无优惠商品卡；图片内容与安全规则复用正式用户生图链路。游客可预览 Create 页面，但上传、AI 润色/生成和正式创建角色，以及主动消息、个人资料编辑、优惠领取和其他非聊天写操作必须要求认证。

`Current`：游客已具备 AI 语音回复、语音输入和附件上传能力，复用正式 TTS、ASR、上传校验和附件处理，同时继续使用独立 guest session、额度、受保护资源、幂等/并发保护和过期清理；生图仍为成功 1 张。

`Current`：游客实时通话复用正式通话的 WebSocket、STT、AI 回复、TTS、商品和前端通话链路；每次成功落库的最终用户转写按 1 条计入共享 30 条额度，重复回合、空音频、识别失败、AI 回复和语音播放不计数。通话没有独立时间额度；同一 guest session 与同一网络同时最多一通，全局游客同时最多 50 通，正式账号行为不受游客护栏影响。

`Current`：游客遇到受限操作时保留当前站点与对话上下文并展示注册/登录引导；同站点认证成功后原子转移或合并文字、商品卡、ready 图片、ready AI 语音、附件和通话审计记录，撤销旧 guest token。过期清理只删除未承接的游客资源，并与承接事务协调锁，避免文件或归属竞态。

`Current`：游客期间不进入正式长期记忆、摘要、索引、主动消息、促销投放或用户统计。承接后仅迁入的文字可异步补建索引/摘要；游客商品和图片永久排除。具体规则见 [游客聊天与认证承接规格](../superpowers/specs/2026-07-10-guest-chat-and-auth-handoff-design.md)。

`TBD`：游客后续的额度调整与跨设备恢复，需以真实使用数据和独立规格确认。

## 外部账号和订单的演进

`Approved direction`：外部商城账号绑定必须是用户主动授权且可验证的流程；绑定关系与 AIOVE 用户账号分开存储，不能依据邮箱猜测关联。

`Approved direction`：订单数据只在外部身份验证完成后由可信服务端同步，用于用户画像、已购商品和忠诚度权益；不复制外部商城密码，不把整库用户账号导入为 AIOVE 登录账号。

`Approved direction`：未来 SSO 仅服务于已在外部站点登录且经过安全授权的用户；普通独立站访客仍应走游客或普通注册链路。

`Approved direction`：Shopify 站点优先采用 Customer Account OAuth 作为用户主动授权入口；入口属于当前站点，不得因为另一个站点已配置而出现或获得能力。商品只读 Token 只能证明该站点已配置商品数据源，不能证明 Customer Account OAuth 可用，也不能建立外部身份绑定。

`Current`：站点授权登录入口同时受“该站点已配置商品只读 Token”和站点级 `shopify_login_enabled` 开关约束；两项都满足才允许在登录页展示。管理员关闭开关只隐藏该站点登录入口，不删除 Token，也不影响商品、订单或 Kitshop 数据链路。

`TBD`：Customer Account OAuth 的 Provider 配置字段、callback、最小 scope、AIOVE 账号创建/匹配、订单同步、解绑、删除与失败恢复仍需独立规格确定。当前候选方式、适用条件和待确认问题统一记录在 [登录与外部商城身份方案评估](../superpowers/specs/2026-07-13-login-and-commerce-identity-options.md)；除上述已批准方向外，该评估中的其他候选方案不代表已批准。
