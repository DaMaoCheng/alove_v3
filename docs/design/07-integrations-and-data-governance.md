# 07. 集成与数据治理

## 当前集成事实

`Current`：商品读取支持站点绑定的 Shopify Admin 只读商品源；访问 token 在服务端加密保存，只由后端可信商品目录读取器使用，不进入 URL、浏览器、接口响应或日志。前台和游客接口可以返回该目录中通过可见规则的商品数据，但客户端不得直接持有或调用 Admin token。

`Current locally`（尚未部署）：商品读取增加站点绑定的 TTMall 只读商品源。配置只保存 API 主机和网站 ID；短期 JWT 由后端通过 `/v1/token/:websiteId` 获取、合并并发请求并在内存中按过期时间缓存，401 时最多刷新一次。JWT 不落库、不进入浏览器、接口响应或日志。API 主机，以及上游返回的 storefront/CDN 主机均经过 HTTPS、公网地址校验；读取拒绝跟随重定向，避免跳转到未经校验的目标。Token 与网站信息缓存均有 TTL 和数量上限。

`Current`：商品接口在可信目录之前执行身份和站点校验。普通账号只能读取 active 的所属站点，管理员可以跨站；无效或停用站点不回退默认站。游客必须来自 Alove 公开应用并通过站点开关和网络额度。正式账号商品请求按账号与站点执行窗口额度和同时在途上限，响应剥离内部 source snapshot 和精确库存字段。

`Current`：Google 登录已接入代码与账号关联模型；真实线上可用性仍受外部网络条件影响，应按运行状态复查，不能仅凭代码存在宣称可用。

`Current`：站点公开品牌由独立白名单接口提供，只包含稳定 ID、名称、slug、公开网站链接、Logo 和不含密钥内容的能力布尔值。商品详情、Kitshop 与认证页不得为了显示站点图标或判断能力而直接读取 Shopify Admin 配置或商品 token。

`Current`：AIOVE 当前没有外部商城客户登录打通、订单导入或订单同步能力。现有外部账号关联结构不能直接等同于商城账号绑定功能。

`Current`：Shopify Customer Account 入口位于 Google 登录下方，并使用当前路径已经解析的站点名称和 Logo。当前以该站点是否配置商品只读 Token 作为禁用预览的显示门槛：未配置则完全隐藏，已配置但没有 OAuth action 时只显示禁用预览。该门槛是阶段性 UI 承载规则，不得被解释为 OAuth 配置检测或登录能力证明。

`Approved direction`：真实 Shopify Customer Account OAuth action 接入后，按钮才可启用并进入授权流程。商品只读 Token 与 Customer Account OAuth 的 client、scope、callback 和用户授权凭证必须分开管理；任何站点只能使用自己的配置，不能继承其他站点的登录能力。当前尚未实现 callback、Customer Account token、AIOVE 账号匹配或外部账号绑定。

## 数据可信边界

- `Current`：商品价格、库存、链接、活动命中、角色可见性和权限必须从受控服务端来源获取。
- `Current`：模型、浏览器 URL 参数和前端展示字段都不是外部身份、订单归属或优惠资格的可信证明。
- `Current`：服务端日志、运维配置和密钥不得进入产品文档、前端响应或模型提示词。
- `Approved direction`：外部订单只在用户授权、身份验证、服务端拉取/验签和最小字段映射完成后进入用户画像。
- `Approved direction`：外部数据同步需要保存来源、同步时间、状态和可追溯引用，并支持失败重试和用户解绑后的停止使用。
- `TBD`：不同商城的认证方式、订单保留期、删除请求、跨站点数据隔离、隐私告知和合规要求，需要在接入前逐项评估。

## 集成实施门槛

任何新增外部身份或订单集成必须先完成独立规格，至少写明：授权方式、最小数据字段、信任边界、同步触发、失败/撤销流程、权限校验、数据删除和验收样例。未经这些定义，不得用“导入用户数据”或“自动登录”替代真实身份设计。
