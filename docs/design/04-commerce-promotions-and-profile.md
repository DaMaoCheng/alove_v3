# 04. 商业、权益与用户画像

## 当前商业能力

`Current`：站点可配置可信商品源，Kitshop、聊天、搜索、游客商品卡、商品详情刷新和广告活动选品均使用当前站点的同一可信商品目录。Shopify 站点以服务端只读 Admin API 为商品事实来源；只要商品为 `ACTIVE` 且已发布到 Online Store，就允许在 Alove 展示，不受独立站主题中的登录显隐、首页楼层显隐或游客搜索显隐影响。Draft、Archived 和没有 Online Store URL 的商品不展示。

`Current locally`（尚未部署）：可信商品源增加 `TTMall`。管理员只配置 HTTPS API Base URL 与网站 ID；Alove 后端自动取得并在内存中缓存临时 JWT，不保存或回显令牌。TTMall 商品继续映射到现有统一商品结构，因此 Search、正式账号/游客 Chat、活动选品、详情、尺码表、定制项和 Kitshop 不建立专属前端实现。TTMall 没有接入变体购物车能力，详情 CTA 明确跳转可信独立站商品详情，不伪装成 checkout。商品裸价使用 TTMall 网站信息返回的汇率表转换成当前站点币种；来源没有该币种汇率时不显示价格，不把裸数值直接套成站点币种。Kitshop 按 TTMall 首页接口顺序使用首个有效楼层，缺少订单销量接口时 `Best Sellers` 只从其余公开楼层补齐，不伪造销量。

`Current`：商品卡/气泡保存站点 slug 和商品快照，商品详情中的站点名称、链接和 Logo 读取统一站点品牌配置。显式 Logo 为空时才使用公开网站或商品 URL 的 favicon；更改站点品牌不会改写商品、活动或历史消息数据。

`Current locally`（尚未部署）：商品详情定制项由服务端按当前站点商品公开 URL 读取 Avis/Aris option set，再以 `customizationOptions` 白名单传递到 Search、Kitshop、Chat 和实时通话共用的详情面板。只返回真实商品存在的 option type、label、value、price、required 和安全图片；接口失败、限流或结构未知时返回空定制列表，不使用预览示例或硬编码球员。当前只保存面板内的定制选择与附加价展示，尚未把定制属性写入 Shopify cart/checkout。

`Current locally`（尚未部署）：商品尺码表不再实时抓取独立站商品页。服务端按可信商品的变体 SKU 使用最长前缀确定性匹配项目内维护的 10 类通用尺码表，并将同一 `sizeChart` 安全结构提供给 Search、Kitshop、Chat 和实时通话的共用详情面板；未知、空白或未登记的 SKU 不显示尺码表，不按标题或模型判断猜测。商品价格仍按原有独立刷新规则更新，尺码表不参与第三方页面缓存和限流。

`Current`：Kitshop 固定为两层货架：第一层取当前站点独立站首页按顺序遇到的第一个有效商品栏目，保留该栏目标题和符合可信目录规则的商品顺序；第二层固定为 AIOVE `Best Sellers`，由最近 30 天净销量前五、最近 60 天最多五个未重复热销商品以及首页其他栏目的随机目录商品组成，补足到最多 15 件后统一混排。净销量使用 Shopify 已支付/部分支付订单的 `currentQuantity`，排除测试、取消、全额退款和已移除数量；同一商品不得重复，也不得重复第一层商品。随机结果随 4 小时缓存或管理员手动刷新更新，普通页面刷新保持稳定；登录用户读取到过期或空缓存时只触发后台单次刷新，不等待 Shopify 订单接口。只有 `ACTIVE` 且已发布到 Online Store 的商品可以进入货架；独立站主题登录显隐不参与过滤，其他首页栏目不得继续生成额外前台货架。

`Current`：后台促销活动可按站点、角色范围、时间、关键词、商品和折扣码配置；活动商品搜索保留运营人员输入的名称或 SKU 原文，不经过聊天语义改写，从而支持直接粘贴 Kitshop 完整商品标题并命中同站点可信目录。活动命中、优先级、去重和实际投放由后端确定，不由前端或模型决定。

`Current`：后台折扣码页面登记独立站已经创建的站点码和网红码，不调用 Shopify 创建、修改或删除折扣。页面按 active 站点、归属类型和派生状态筛选；同站点 code 忽略大小写唯一；没有订单归因前不显示“已使用次数”，也不提供领取、核销或用户资格发放。

`Current locally`（尚未部署）：管理员在当前站点输入至少两个字符时实时搜索 Shopify 折扣码，必须从返回候选中选择。创建和编辑保存前由服务端使用当前站点 token 对 exact code 再查询，优惠说明、优惠类型、门槛、有效期与 Shopify 状态自动只读回填并保存为可信快照；后台不再允许人工填写这些事实字段。读取失败、code 不存在或站点未配置可用源时拒绝保存，不把输入内容伪装成真实优惠。

`Current locally`（尚未部署）：商品详情不会永久信任登记时快照。快照超过 15 分钟或 scheduled 折扣到达开始时间时，服务端按站点和 code 刷新 Shopify；旧的本地开始/结束时间不能阻断 Shopify 提前开始或延长后的刷新。写回使用乐观锁，刷新失败时不返回旧优惠或旧预计价格，并进入短暂冷却。搜索接口只对具备促销写权限的管理员开放，并有服务端缓存和频率限制。

`Current`（本地已实现，尚未部署）：具备明确角色上下文的 Chat 和实时通话商品详情会实时查询角色当前有效折扣码。前台（mascot）角色只使用其所在站点的 `site` 码；Creator 角色只使用同站点且归属于该角色 owner 的 `creator` 码。一个角色可展示多个码，用户可逐个复制并一次选中一个；角色切换、跨站商品或实时资格变化时不得残留旧码。Search 和 Kitshop 没有角色上下文，不隐式选择角色，也不返回角色码。

`Current`（本地已实现，尚未部署）：正式用户文字、附件、语音和实时通话共用同一折扣资格与回复链路。模型不会收到真实 code、优惠说明、归属字段或结束时间，只能在已确认的商品对话中返回“适合提优惠”的内部指令。用户明确询问折扣或该指令被允许触发时，最终可见文本和 TTS 由服务端使用真实 code 与优惠说明口语化组装；普通闲聊不能自行触发折扣码。该全局规则同时覆盖前台（mascot）和网红（creator）。角色不能猜码、改码、复述已失效历史码，或虚构折扣力度、适用范围、叠加、赠品和期限。游客和主动消息不注入这套正式用户折扣上下文。

`Current`：用户画像和聊天记忆可记录兴趣及已购商品相关信息；当前未接入外部商城订单同步，因此不能把外部购买记录当作已验证画像。

## 权益模型方向

`Approved direction`：后续权益以通用作用域建模，不按特定站点硬编码：

- `site`：站点注册用户可用的站点权益。
- `creator`：满足创作者/推广来源上下文时可用的推广权益。
- `loyalty`：完成外部账号绑定并验证订单后可用的购买或忠诚度权益。

`Current`：游客不能获得、展示或由 AI 发送具体折扣码；游客商品链路显式跳过活动投放并剥离优惠字段。已注册但未绑定外部账号的用户是否可获取站点权益，仍按每个活动的确定性资格规则判断。

`Current`：游客可接收当前站点可信商品源的普通商品卡；商品卡、AI 文案和跳转上下文剥离活动、折扣码和权益字段，且不触发活动投放记录、优惠资格或长期画像。

`Current`：普通正式账号的 Kitshop、商品搜索和商品详情刷新固定使用 active 的账号所属站点；管理员可跨站运营。商品接口严格解析显式站点，停用或不存在的站点不能回退默认站。游客商品读取要求当前站点已开放游客能力并通过 Alove Origin/Referer 与网络额度校验；正式账号执行独立的账号级商品读取额度和同时在途请求上限。Search、Resolve、Kitshop 和聊天商品消息均不向前端返回服务端内部匹配对象或 Shopify 精确库存数量。

`Approved direction`：完成可验证外部账号绑定后，用户才可获得依赖订单的忠诚度权益。

`Current`（本地已实现，尚未部署）：AI 只能在后端已判定资格并返回可用折扣时表达优惠；不得自行生成、猜测或承诺折扣码。普通折扣询问返回一个有效码，明确询问全部时最多列出五个，结合近期对话的简短追问可返回尚未提及的下一个码或明确说明没有更多。

`Current locally`（尚未部署）：用户在商品详情选中一个有效码后，由服务端重新校验角色、站点、商品 URL、变体和折扣资格，生成 Shopify `/discount/{code}?redirect={target}` 链接；没有有效码或生成失败时回退原普通购买链接。当前只确认 Alove 生成了带码链接，不声称 Shopify 已实际应用折扣。真实 Shopify 应用结果属于后置验收。

`Current locally`（尚未部署）：商品详情只在规则可以确定性计算时展示预计折后价：active、无门槛、全商品、全客户的百分比折扣，或与商品展示币种一致的固定金额折扣。当前 Buy now 固定生成单商品、数量 1 的购物车，因此无门槛整单固定立减也可直接从当前商品价扣除。选码、换码、取消选择和切换带独立价格的尺码都会重算。满减、免运费、买赠、App 折扣、限定商品/客户和币种不确定时不计算价格，继续由 Checkout 最终确认。
