# 06. 后台与运营

## 当前后台职责

`Current`：管理员可管理站点、网红角色、通用角色、站点前台、首页轮播、Kitshop 缓存刷新、广告活动、折扣码登记、知识库、用户反馈、账号和错误日志。后台数据修改必须通过管理员授权接口；逐页面字段、控件和权限见 [页面与字段规范](../system/pages/README.md)。

`Current`：站点配置是多站点运营的控制面，包含 slug、地区映射、前台、游客聊天、商品源和支付方式等；当前页面没有 active/inactive 编辑控件。账号管理可查看并调整用户站点归属，属于影响权限与体验的高风险操作。

`Current locally`（尚未部署）：商品源类型支持 `Shopify Admin API` 与 `TTMall`。TTMall 只要求 API Base URL 和网站 ID，临时访问令牌由服务端自动获取；切换类型时页面只启用当前类型字段，服务端也会清除不再适用的 Shopify 凭据。

`Current`：站点商品只读 Token 是服务端商品源配置。其“是否已配置”状态同时作为当前登录页 Shopify 品牌预览的显示门槛，但 Token 内容不公开，且该状态不代表 Customer Account OAuth 已配置或可登录。新增站点没有 Token 时不显示预览；配置后按同一通用规则显示。当前站点管理保存逻辑支持新增或替换 Token，尚未提供明确的移除 Token 操作。

`Current`：商家线索、交易支付、成本与利润仍是静态待办入口；折扣码已是本地可用的真实登记与管理页面，但尚未部署线上，也不承担 Shopify 折扣创建、核销、订单归因或财务结算。

`Current`（Local verified）：折扣码页面支持站点/网红两类归属、active 站点和同站点可用 creator 选项、无限期/固定期限、启用开关、列表搜索与状态筛选。网红账号必须属于所选站点且拥有未归档 creator 角色；站点归属会清空 creator。状态由 enabled、开始时间和结束时间实时派生为 `scheduled / active / expired / disabled`。

`Current`：账号管理以“正式账号”和“游客会话”两个顶层标签区分身份数据。游客会话只提供管理员只读统计、站点/状态筛选、会话详情与游客阶段对话审计；不会创建临时 `users` 账号，也不提供游客 token、cookie 或跨设备身份标识。

## 运营规则

- `Current`（已发布）：创建或修改促销活动时，运营配置必须落在明确站点和时间范围内；商品、折扣码、活动状态和投放结果由后端保存。进行中活动不能保存已经到期的结束时间，前端小提示和服务端会双重拒绝；进行中活动到达结束时间后由服务端自动归档，后台列表读取会即时补偿尚未归档的遗留数据。
- `Current`（已发布；本地真实功能验证，生产部署、静态门禁与健康检查通过）：运营可从站点前台选择当前有效活动并立即启动投放。候选活动、目标账号、活动去重和成功/失败结果均由后端确定；管理员手动投放不检查、不占用自动主动消息额度；关闭进度弹窗不会停止后台任务。当前尚未执行真实生产账号投放，因此不标记为生产完整链路验证。
- `Current`（已发布）：手动投放失败结果按脱敏原因分类展示人数，不暴露用户身份或底层异常原文；“已发广告”只统计至少成功发送给一名用户的任务，并在本次投放完成时即时更新当前前台行。
- `Current`：知识库可按全局、站点或定向范围配置；AI 只读取与当前角色和站点匹配的内容。
- `Current`：游客后台统计以 guest session 为单位；注册承接后只展示原游客阶段产生的消息，不得把正式账号后续聊天计入游客数据。
- `Approved direction`：外部账号绑定、订单同步和优惠资格未来需要后台可审计的配置、同步状态、失败记录和人工处理入口，但不应在第一期把所有流程塞进现有账号管理页。
- `TBD`：站点迁移审批、订单纠错、优惠人工补发、运营角色分级权限和报表口径，需在相应业务规格中定义。

## 运营边界

`Current`：后台可见或可编辑的数据不等于自动对 AI 开放。涉及外部身份、订单、优惠和个人画像的数据必须先通过服务端的范围、权限和最小化注入规则。
