# 03. 角色、聊天、记忆与 AI 行为

## 角色与激活

`Current`：角色是统一 AI 角色实体。前台、网红角色、通用角色和用户创建角色共享角色、会话、记忆和消息基础能力。

`Current`：站点前台在用户注册后自动激活，且用户不能删除该前台联系；网红角色按站点可见，通用角色按公开/私有规则可见。

`Current locally`（尚未部署）：前台（mascot）可维护一个独立的 5 槽问候素材库，其中前 4 槽为图片、第 5 槽为 MP4 视频。新会话首次写入文字问候后，服务端先判断视频槽：视频 ready 时固定发送视频；没有视频时，代码通过安全随机数在 ready 图片数组中抽取一个编号并发送对应图片，不调用模型选素材。后台素材库只提供空槽点击上传、已就绪缩略图点击放大/播放和单槽删除；图片通过安全校验后立即缩放并转为 WebP，视频通过 MP4 校验后立即压缩为 H.264/AAC MP4，只有压缩成功的文件才保存为 ready。同一会话、刷新、恢复和语音重试不会重新抽取。素材库是运营预先上传的公共资源，不属于用户即时生图：不消耗用户或游客图片额度、不进入图片队列、记忆、摘要或受保护聊天图片资产。删除只改变未来新会话，已经投递的历史素材 URL 快照必须继续可见；图片和视频均不存在时只保留文字/语音问候，不能创建空媒体消息。

## 提示词分层

`Current`：回复上下文由角色私有人设/说话风格和全局回复策略共同组成。角色层负责身份、语气、个性、语言和特定知识；全局层负责所有角色共同遵守的产品回复质量规则。

`Current locally`（尚未部署）：前台（mascot）和网红（creator）共享“站点优先”规则。除非用户明确询问 Alove 平台本身，否则商品、购物、订单、配送、售后、服务和足球相关问题均以当前路径绑定的独立站内容及已验证上下文为准；不得把独立站问题擅自改答为 Alove 功能或创建虚拟角色。

`Current locally`（尚未部署）：前台和网红在可信上下文仍无法解决独立站问题时，应按人设先明确说明限制，再同时给出两种自愿联系方式：用户可直接在聊天中留下邮箱，或在首页右上角反馈入口填写。角色只能说明团队成员会在有进展或解决方案时跟进，不能承诺自动或即时通知；已能解决的问题不应为收集邮箱而额外追问。聊天原文仅供后台人工跟进，但邮箱在进入模型上下文前必须替换为不可还原的联系标记，模型不得复述、猜测或暴露邮箱。

`Current`：全局策略禁止为了延续聊天而臆测用户意图，尤其不能无依据地以 “A or B?” 这种二选一追问收尾。完成当前请求确有必要的澄清（例如明确球队、尺码或预算）仍可提出。

`Current`：模型不能决定权限、折扣资格、路由、库存、价格或活动命中。它只能基于服务端提供且允许注入的上下文自然表达结果。

`Current locally`（尚未部署）：图片生成只在用户明确表达照片、图片、自拍生成或明确的角色上身拍照意图时触发；普通商品浏览、查看、展示和购物表达不能被推断为生图请求。

`Current locally`（尚未部署）：游客提出商品需求但可信商品源未命中时，模型只能根据当前角色人设选择 `warm`、`playful`、`direct` 或 `encouraging` 四种语气令牌之一，不能直接生成用户可见的商品回复。服务端按语气令牌和可信解析出的球队/款式生成自然说明与唯一澄清问题；模型任意自由文本不会展示，具体商品、价格、库存、尺码可用性、链接、结账、配送、折扣和内部系统错误无法进入最终文本。

`Current locally`（尚未部署）：折扣回复属于前台（mascot）和网红（creator）共用的全局行为规则。后端先确定当前角色可使用的 code 和优惠说明；用户明确询问折扣时，由后端用口语化句子组装真实优惠，不能把 code、金额、比例、范围、期限或叠加规则交给模型自由生成。已确认的商品对话中，模型只收到“此处是否适合提优惠”的内部指令协议，不接收真实 code 和优惠事实；模型可依据角色人设决定是否返回该指令，但一旦触发，最终可见文本和 TTS 仍由后端使用真实 code 与优惠说明组装。普通闲聊返回该指令不会生效，模型自行编造的折扣内容也会在落库前被移除。

## 对话、商品与记忆

`Current locally`（尚未部署）：正式账号和游客的新会话都从可信站点记录初始化默认语言。确定性优先级按角色来源拆分：已有会话先使用已保存语言，正式用户已有角色激活语言偏好继续优先；管理员创建、后台维护及系统预置角色的新会话使用“当前站点默认语言 → 角色资料语言 → English”，因此同一个角色可在不同语言站点动态输出；用户自行创建且 `source_type=user` 的角色使用“创建时选择的角色语言 → 当前站点默认语言 → English”，站点不能覆盖用户的创作选择。用户明确要求回复、书写或说某种语言时才更新会话或激活偏好，仅仅使用另一种语言发消息不会自动改写。旧会话不批量回填，刷新不能用站点默认值覆盖已经保存的会话选择，文字、语音回复和实时通话复用同一个最终语言结果。该机制只选择输出语言，不翻译角色名称、人设、开场白或其他角色内容。

`Current`：聊天消息、附件、商品气泡、语音和生成图片属于会话数据；商品信息应由站点绑定的可信商品源提供，商品展示可使用快照并按规则刷新。

`Current locally`（尚未部署）：搜索页、正式账号聊天和游客聊天共享同一份结构化商品需求、最多五次的有界召回、严格候选过滤和排序执行器。用户在一条或多条消息中明确给出的球队/自由目录锚点、主客/第三/复古款、颜色、赛季、受众、年龄、商品类型、商品特征和印号必须持续累计；角色文本、语音和商品气泡不能清空用户条件。只包含补充字段的短消息应继承最近需求；已经自行包含目录锚点和商品条件的新请求则以本条为准，不能被上一轮的颜色、款式、定制或印号污染。切换球队时旧球队的颜色、赛季和特征不得泄漏到新需求；“不要门将款”“普通款”“不要印号”“不要定制”等纠正必须清除对应旧条件。只有完全满足硬条件的商品才能发送；年龄尺码仍可按已批准规则提供最近真实尺码，并明确说明差异。条件不足时只澄清一次最有价值的信息，条件充分但无匹配时只做一次角色化道歉并提供搜索/反馈承接，二者不能同时出现；若模型已说出邮箱或反馈承接，系统不得重复追加同义文案。商品源缺失、上游抛错或上游明确返回异常时均独立表示为暂时不可用，不能伪装成无匹配。

`Current`：用户记忆用于支持长期个性化，例如喜爱球队、球星和已购商品等；记忆提取需要服从既有分类、隐私和后台可见性规则。

`Current`：自动主动消息和自动匹配的促销投放使用确定性调度、站点、账号级频率、上一条回复门禁和去重规则。管理员在前台管理中显式启动的手动广告属于独立运营动作，不检查也不消耗自动主动消息额度，但仍必须执行活动/账号去重、站点、角色、账号状态、前台激活、正式会话和活动有效性校验。

## 游客聊天与承接

`Current`：游客聊天按角色分别保存临时会话；只有产生过用户实际发言的角色会计入游客对话角色数并在游客侧栏恢复。文字、无优惠商品卡、一次成功图片、ready AI 语音、附件和通话审计记录会在同站点认证时按角色转移或合并；未注册期间不触发优惠、主动触达或长期敏感画像。图片失败不消耗唯一资格，且只能由当前站点内已激活角色生成。

`Current`：游客与正式账号的聊天交互能力保持一致，包括 AI 语音回复、用户语音输入、附件和实时通话；身份、额度、记忆、促销及资源保留边界仍按游客规则执行。游客 AI 语音复用角色音色和正式 TTS 链路，游客输入复用正式 ASR/附件校验，不能另建弱化的平行实现。

`Current`：游客开场白与 AI 文字回复已复用角色音色、正式语音模型选择、TTS 资产和受保护播放链路。文字先可靠落库，TTS 失败不回滚文字；同一消息复用唯一语音资产，支持两次生成尝试、进程中断恢复和过期游客文件清理。

`Current locally`（尚未部署）：聊天语音气泡优先使用语音资产保存的真实时长；旧资产时长缺失或为 `0` 时，服务端根据受支持的固定码率音频格式和实际字节数恢复时长，不再按文字长度估算。该规则由正式账号、游客及所有站点的共用消息映射链路执行。

`Current`：游客语音输入先经过正式上传安全校验和 ASR，再作为普通用户文字进入同一聊天链路；附件复用正式格式/大小校验和 AI 上下文规则。两者与文字共用游客消息额度、幂等键和并发护栏，附件与语音资源只允许所属 guest 或承接后的正式账号读取。

`Current`：游客实时通话的最终转写先以稳定 call/turn key 写入游客会话并原子占用 1 条共享消息额度，再生成角色文字、商品与语音回复；同一回合重试不重复落库或扣数。通话不按时间限制，但继续受单活跃通话、全局并发、音频输入和 Provider 背压护栏控制；失败回复可从已落库转写恢复，不复制用户消息。

`Current`：承接后的游客文字通过可恢复异步任务进入允许的索引和摘要；游客商品卡与图片保留在聊天历史中，但凭持久来源标记永久排除在长期上下文之外。
