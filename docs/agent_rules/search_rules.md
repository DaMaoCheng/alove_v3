# 联网搜索与网页抓取规则

本文件用于最新信息查询、第三方文档核验、版本兼容确认、线上报错检索、网页内容抓取和外部事实验证。

## 1. 主动调用原则

满足触发条件时，Agent 默认主动使用联网工具，不需要等待用户再次要求。

例外情况只有：

- 本地代码、项目文档、已打开网页或用户提供材料已经足够确认；
- 用户明确要求不要联网；
- 问题只需要解释已知概念，不依赖最新事实；
- 当前任务涉及隐私、密钥、账户、付费后台、登录墙或受限内容，联网前必须先确认边界。

如果没有联网但问题属于触发条件，必须说明为什么没有联网。

## 2. 触发条件

出现以下任一情况时，必须主动使用联网工具：

- 问题依赖最新信息，而本地文件无法确认；
- 需要查询第三方官方文档、发行说明、版本差异、兼容性说明；
- 需要检索线上报错、社区讨论或公开知识；
- 需要读取某个网页正文，而不是只看搜索摘要；
- 需要确认价格、政策、产品能力、接口说明、发布时间等外部事实；
- 用户明确要求“联网搜索”“查一下网上资料”“抓取网页内容”；
- 本地排查连续失败两次，且错误可能与外部版本、依赖、平台行为或已知问题有关；
- 用户给出 URL，并要求总结、核对、提取、分析或基于页面内容继续工作。

## 3. 本项目常见触发场景

在 `alove-page-rebuild` 中，以下问题默认优先考虑联网验证：

- Google 登录、第三方 OAuth、Auth 文档、回调限制、浏览器策略；
- Shopify 商品搜索、公开 API、Storefront 行为、网页搜索 fallback；
- ElevenLabs、阿里云 ASR、第三方语音或实时通话文档；
- 依赖升级、框架版本兼容、外部 SDK 行为变化；
- 线上报错、社区已知问题、服务端平台行为差异；
- 用户给出第三方后台页面、活动页面、商品页面或帮助中心链接，要求核对或抓取内容。

## 4. 工具选择

当前已配置的工具，以当前会话可用工具为准。

默认路由：

- 不知道具体 URL，只知道问题或关键词：先用搜索工具。
- 已有明确 URL，且需要页面正文：直接用网页抓取工具。
- 搜索结果只提供摘要，不足以支撑结论：继续抓取关键页面正文。
- 查询官方 API、SDK、依赖、产品能力：优先搜索官方文档，再抓取官方页面。
- 排查报错：先搜索精确错误文本；如果结果分散，再加入框架、库名、版本号缩小范围。

## 5. 搜索流程

每次搜索前先明确一个具体问题，例如：

- 这个 API 当前参数是什么；
- 这个报错是否是已知问题；
- 这个库的最新版本是否改了行为；
- 这个页面原文是否支持某个结论。

默认流程：

1. 查询 1 到 2 组高质量关键词。
2. 优先选择官方文档、官方博客、官方仓库、发行说明、可信技术来源。
3. 对关键来源读取正文。
4. 对比来源时间、版本、适用范围和本地上下文。
5. 输出结论时说明依据来自搜索结果、抓取页面还是本地文件。

## 6. 搜索纪律

- 不要无目的泛搜。
- 不要只根据单一结果下结论。
- 不要把搜索摘要直接当成最终事实。
- 不要用非官方帖子覆盖项目已有代码事实，除非能解释适用性。
- 搜索结果必须结合发布时间、适用版本、上下文范围判断是否可用。
- 如果搜索工具不可用、结果不足或来源可疑，必须明确说明未完成联网验证。

## 7. 抓取纪律

- 抓取前先确认 URL 与当前问题相关，不要无关扩散抓取。
- 抓取结果要区分“页面原文”与“Agent 总结”。
- 对长页面优先提炼与当前问题直接相关的部分，不要原样倾倒大量正文。
- 涉及登录墙、隐私内容、用户数据或受限页面时，不要擅自尝试绕过访问限制。
- 抓取失败时，说明失败原因，并尝试使用搜索摘要、官方替代页面或用户提供内容继续判断。

## 8. 输出要求

- 结论必须说明依据来自本地文件、搜索结果还是抓取页面。
- 外部信息与本地代码冲突时，必须显性说明冲突点。
- 无法确认时，要明确说不确定，不得把搜索摘要当作确定事实。
- 如果用户问的是操作建议，要把搜索得到的事实转化为可执行建议，而不是堆链接。

## 9. 禁止事项

任何时候都不要：

- 把搜索摘要直接当成最终事实；
- 只凭单一非官方帖子覆盖项目现有结论；
- 在本地证据已经充分时重复联网搜索；
- 抓取无关页面或与当前任务无关的大量内容；
- 在输出中伪装成“已经验证”，如果实际上没有完成联网核验；
- 把 API key、cookie、token、账户信息或私密页面内容写进规则文件、日志或交付说明。
