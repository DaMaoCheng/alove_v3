# Database Seed Rules

本文件约束数据库 schema、迁移、seed、自检初始化和配置覆盖风险。

## 1. migration 与 seed 的基本原则

- migration 必须幂等
- seed 必须幂等
- 新增字段后必须考虑旧数据兼容
- 不能因为本地方便就让初始化覆盖已有运营配置

## 2. 明确禁止覆盖的配置

默认不得被 seed 或初始化自动覆盖的内容包括但不限于：

- 站点商品 API
- 角色绑定站点
- 活动配置
- 广告商品快照
- 管理后台手工维护的关键字段
- 本地已验证的环境配置

如果必须在 seed 中给默认值，必须用只在空值时补默认的方式，而不是无条件重写。

## 3. 自检执行规则

涉及数据库初始化、迁移、seed 的自检，默认按串行执行。

不要并行跑多个会触发初始化的自检，避免：

- migration 死锁
- seed 竞态
- 数据被相互覆盖
- 自检结果互相污染

如果确实要并行，必须先证明这些脚本不会共享初始化过程。

## 4. 先判断数据问题还是代码问题

当运行结果异常时，必须先区分：

- schema 没加成功
- migration 没执行
- seed 覆盖了新值
- 运行中的数据库不是预期实例
- 自检脚本重置了现场
- 真实代码逻辑有误

禁止不查数据层就直接叠代码补丁。

## 5. 新增商品快照、站点配置、活动字段时

- 创建/读取/更新链路要一起检查
- 匹配结果是否带出字段要一起检查
- 消费字段的消息构造器、页面渲染、自检断言也要一起更新
- release 和更新日志里要明确写清字段边界和兼容行为
