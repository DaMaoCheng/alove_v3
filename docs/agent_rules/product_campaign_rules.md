# Product Campaign Rules

本文件约束商品搜索、商品气泡、广告活动、主动消息和商品跟进回复的确定性行为。

## 1. 先分清代码问题还是配置问题

商品、广告活动、主动消息相关问题出现时，先排查：

- 角色分类是否满足触发条件
- 角色是否绑定了正确站点
- 站点商品 API 是否存在
- seed 或初始化是否覆盖了站点商品配置
- 当前服务是否已重启到新代码
- 前端是否实际传了触发参数

不能在运行配置不满足时，直接往代码里硬塞假逻辑掩盖问题。

## 2. 商品链路必须确定性

以下逻辑禁止只靠模型判断：

- 商品是否触发
- 角色是否允许触发商品链路
- 商品候选过滤
- 活动命中优先级
- 去重
- 纠错后重新选品
- URL、价格、库存、SKU 等字段是否显示
- 商品卡与文本回复的绑定

这些必须写成明确规则、条件判断、清洗器、自检或查找表。

## 3. 商品卡与文本必须同源

- 商品卡和补充回复必须绑定到同一个 selected product 或同一份活动商品快照。
- 如果没有确定商品，只能发澄清文本或失败文本，不能假装在说具体商品。
- 商品卡展示事实，文本只负责自然短句补充；不要让文本复述商品标题、价格、库存、URL、SKU。

## 4. 商品跟进回复约束

当页面已经展示商品气泡时：

- 文本必须是一条短句
- 不得输出 URL
- 不得输出价格、库存、SKU、搜索链接、原始 API 字段
- 不得把商品卡事实再念一遍
- 必要时使用 sanitizer，而不是只靠 prompt

如果模型输出不稳，优先补确定性清洗层。

## 5. 广告活动规则

- 广告活动命中主动消息时，必须明确区分：文本消息、产品消息、delivery 记录三者。
- 同账号同活动去重必须是明确代码规则，不交给模型。
- 商品快照如果已经落库，广告产品气泡优先使用快照，而不是运行时重新拼凑。
- 活动命中结果需要的站点 slug、商品标识、折扣码、快照都应由后端确定返回，不能由前端猜。

## 6. 商品搜索 fallback 规则

- Shopify 或其他外部商品源的 fallback 必须只读，不能偷偷写外部系统。
- 如果使用公开网页搜索或公开产品 JSON 补偿查询，要明确限定在管理员选品等合理场景。
- fallback 是补偿，不应无边界扩大到前台所有搜索。

## 7. 不允许的行为

- 找不到目标商品时跨队乱推荐
- 用错误商品卡迎合用户意图
- 让文本提到与当前商品卡不一致的球队、商品或价格
- 用 prompt 祈祷代替 deterministic filter
- 因为本地配置缺失，就在代码里硬写假商品凑通过
