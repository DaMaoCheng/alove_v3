# 后台：Kitshop、广告活动与知识库

实现状态：`Implemented`。验证范围：`Local code verified`（页面模板、controller、可信商品服务、活动/知识写入服务与 API）。

三个入口均要求管理员身份；刷新 Kitshop 需要 `admin:kitshop:write`，活动写入及可信商品搜索需要 `admin:promotions:write`，知识库写入需要 `admin:knowledge:write`。

## 1. Kitshop 管理 `view=kitshop`

状态：`Current`。这是站点商品缓存、首页栏目识别与刷新状态的运营页。除“刷新当前站点”外全部只读；商品标题、价格、库存和外链必须来自可信商品源，不能在此手改。

### 1.1 页面字段与操作

| 字段/控件 | 输入/默认/来源 | 作用 | 操作结果/错误 |
| --- | --- | --- | --- |
| 站点 | active 站点下拉 | 选择要查看的商品缓存 | 切换后重载该站点全部摘要、栏目与商品；无 active 站点显示空状态 |
| 刷新当前站点 | 按钮 | 强制从当前站点可信商品源重新解析 | 无站点时禁用；成功刷新列表；来源失败、空结果或不完整结果显示警告/错误，并保留上次可信缓存 |
| 缓存商品 | KPI | active 缓存数 | 只读 |
| 已下架缓存 | KPI | inactive 缓存数 | 只读，不表示 Shopify 删除 |
| 首页栏目 | KPI | active 栏目数/识别总数 | 只读 |
| 商品同步时间 | KPI | 最近商品成功同步时间 | 无记录显示 `-` |
| 栏目同步时间 | KPI | 最近栏目成功同步时间 | 无记录显示 `-` |
| 货架规则 | 说明卡 | 解释 Recommended、Best Sellers 和刷新保护 | 只读，不是可编辑配置 |

### 1.2 首页栏目表

| 列 | 内容/用途 |
| --- | --- |
| 标题 | 独立站栏目标题 |
| key | 稳定栏目识别键 |
| 类型 | 识别出的栏目类型 |
| handles | 来源商品 handle 摘要 |
| 商品数 | 当前缓存关联数量 |
| 排序 | 来源/规范化顺序 |
| 状态 | active/inactive |
| 同步时间 | 最近写入时间 |

栏目查询最多显示 40 条。第一页货架取独立站首页首个有效商品栏目；前端只生成“推荐货架 + Best Sellers”两层，不把首页所有栏目逐层复制到 Kitshop。

### 1.3 商品缓存表

| 列/控件 | 内容/规则 |
| --- | --- |
| 商品 | 图片、标题、external key；有 URL 时可新窗口打开 |
| 现价/原价 | 可信商品快照；无值不伪造 |
| 库存 | available/不可用等可信状态 |
| 来源排序 | 来源栏目/商品顺序 |
| 状态 | active/inactive |
| 同步时间 | 最近缓存更新时间 |
| 分页 | 默认 12 条，接口上限 50；加载时禁用重复翻页 |

### 1.4 商品和 Best Sellers 规则

- Shopify Admin 商品源接受 `ACTIVE` 且已发布到 Online Store 的商品；独立站主题是否要求登录才显示，不参与可信目录过滤，因此主题隐藏商品仍可出现在 Alove。
- Best Sellers 最多 15 件：先取近 30 天净销量前 5；再从近 60 天累计净销量排名中取最多 5 个尚未出现的商品；其余从独立站首页除第一货架外的栏目随机补齐；最终混排且所有商品去重。近 60 天排名包含近 30 天销量，但商品 ID 去重，不能误写成单独的第 31–60 天销量窗口。
- 销量数据不可用时必须走现有可解释 fallback，不能由模型猜销量。
- 刷新保护的目标是避免第三方临时失败把完整缓存覆盖成空缓存；页面必须显示真实同步结果。

## 2. 广告活动 `view=promotionCampaigns`

状态：`Current`。活动可供自动聊天匹配和前台管理中的手动投放使用。折扣码当前只是活动字段，完整的资格、领取、一次性绑定、核销和归因系统仍未实现。

### 2.1 筛选与列表

| 字段/操作 | 输入/来源 | 结果 |
| --- | --- | --- |
| 搜索 | 活动或商品文本 | 服务端过滤活动列表 |
| 站点 | 全部或具体站点 | 限定活动 `site_id` |
| 状态 | 全部、draft、active、paused、archived | 只过滤列表，不改变状态 |
| 新建广告活动 | 按钮 | 打开空表单 |
| 活动 | 标题、主动文案摘要 | 打开编辑 |
| 站点 | 名称/slug | 只读列表字段 |
| 角色范围 | all/mascot/creator | 只读列表字段 |
| 商品 | 商品标题、ID、折扣摘要 | 来源于保存时快照 |
| 统计 | CTR、CTA、发送/曝光/点击/详情/跳转 | 只读投放结果；当前缺失或非法统计统一显示 `0` / `0%`，无法区分“未统计”和“真实为 0” |
| 时间 | 开始/结束时间 | 空值表示开放边界 |
| 状态 | 当前状态 | 编辑表单直接修改；进行中活动到达结束时间后自动归档 |

### 2.2 活动字段

| 字段 | 控件/输入方式 | 必填/默认/允许值 | 校验与错误 | 保存效果 | 关联目标 |
| --- | --- | --- | --- | --- | --- |
| 活动标题 | 文本框 | 必填；最多 128 字符 | 空值拒绝 | 后台识别名称 | 活动列表、手动广告 |
| 站点 | 全部已存在站点下拉 | 必填 | 当前页面不按 active 状态过滤；服务端只确认站点存在，inactive 站点也可选择和保存；变更会清空已选商品 | 固定活动与商品/用户边界 | 站点、商品源 |
| 角色范围 | 下拉 | all/mascot/creator；默认 all | 非允许值规范化 | 限定自动/手动可触发角色类型 | Chat、前台 |
| 状态 | 下拉 | draft/active/paused/archived；默认 draft | 选择 active 时，如结束时间已到或早于当前时间，前端提示且服务端拒绝保存 | 只有 active 且在有效时间窗内才可实际投放；到期后自动改为 archived | 活动执行 |
| 商品搜索 | 文本框 | 先选站点；至少 2 字；350ms 防抖 | 调用当前站点可信目录；最多展示 8 个候选；查询失败显示错误 | 只搜索，不保存 | Shopify/商品缓存 |
| 已选商品 | 必须点击候选结果 | 正常 UI 候选来自当前站点可信目录；服务端要求商品 ID、标题和非空 URL，不能只留输入文字 | 站点变化或候选不完整时清除/拒绝；服务端当前只对 URL 做非空和长度处理，没有复核协议、可信目录或来源，管理员直接调用 API 可写入任意字符串，这是安全校验缺口 | 保存商品快照并原样用于后续商品消息；不能把现状描述为服务端已保证安全 URL | 聊天商品卡、广告 |
| 折扣码 | 文本框 | 可空；最多 64 字符 | 仅字符字段校验 | 写入活动文案/快照；不自动授予用户权益 | 未来优惠体系 |
| 关键词 | 文本框，仅英文逗号 `,` 分隔 | 可空；UI 最多 255 字符；服务端转小写、去重，最多 20 个 | 中文逗号当前不会拆分，会连同整段保存成一个关键词 | 自动聊天匹配条件之一 | Chat intent |
| 优先级 | number | 1–9999；默认 100 | 服务端取整/限幅 | 多活动候选的确定性排序因素 | 活动匹配 |
| 开始时间 | 自定义可见层 + 原生 `datetime-local` 交互层 | 可空 | 点击文字区或日历 icon 打开原生 picker；支持键盘输入；有效值转 ISO | 限定开始时间 | 活动资格 |
| 结束时间 | 同上 | 可空 | 必须是有效日期且严格晚于开始时间；状态为 active 时还必须晚于保存时的当前时间，否则小提示弹窗说明时间设置有误并保存失败；draft/paused/archived 可保留历史结束时间 | 限定结束时间；active 到期后由服务端定时归档，列表读取也会即时补偿 | 活动资格、生命周期 |
| 主动文案 | textarea | 必填；最多 1000 字符 | 空值拒绝 | 受控广告消息；模型不得自行生成折扣承诺 | Chat/手动广告 |

日期可见层格式为 `YYYY/MM/DD HH:mm`，空值显示日期时间占位；原生日历图标按深/浅主题显示。picker 的浏览器内部选中样式由浏览器控制，不应通过禁用输入或遮断点击来“修复”。

可信商品搜索通过后端 Shopify Admin/可信目录执行，可找到独立站主题对未登录用户隐藏、但仍为 `ACTIVE` 且发布到 Online Store 的商品。前端不能自行声称商品存在、价格正确或有库存。游客链路显式跳过活动并剥离 campaign、折扣和权益字段。

## 3. 知识库 `view=kb`

状态：`Current`。页面管理知识文档、检索关键词、优先级和绑定范围。知识绑定控制检索适用对象，不替代用户身份或后台权限校验。

### 3.1 搜索、列表和操作

| 字段/操作 | 输入/来源 | 结果 |
| --- | --- | --- |
| 搜索 | 名称/ID、分类、摘要、精准或模糊关键词 | 客户端过滤当前已加载文档 |
| 分类 | 全部或当前分类 | 客户端过滤 |
| 文档 | 名称、ID | 编辑入口 |
| 分类 | category label/key | 只读列表字段 |
| 适用范围 | targeted/site/global | 显示当前 scope |
| 优先级 | P0–P5 映射 | 只读；数值越高越优先 |
| 绑定数 | 角色/站点目标数 | global 显示 `-` |
| 更新时间 | 最近更新时间 | 只读 |
| 新建/编辑 | 按钮 | 打开表单；新建会进入 AI 处理等待状态 |
| 删除 | 行按钮 + 确认 | 事务删除文档、sections 和绑定并写审计日志；当前无回收站，属于不可逆操作 |

### 3.2 知识字段

| 字段 | 控件/输入 | 必填/默认/允许值 | 校验与错误 | 保存效果 | 关联目标 |
| --- | --- | --- | --- | --- | --- |
| 知识库名称 | 文本框 | 服务端必填；最多 128 字符 | UI 未标 required，但空值仍会被服务端拒绝 | 文档 label | 列表、检索审计 |
| 分类 | 可输入/可选择组合框 | 默认 general；key 最多 64 字符 | 规范化为安全小写 key，并保存 label | 组织与筛选 | KB 分类 |
| 精准关键词 | 文本框 | 逗号、中文逗号或换行分隔；最多 80 项 | 去空项并按数组保存 | 高精度候选词 | retrieval |
| 模糊关键词 | 文本框 | 同上，最多 80 项 | 不能用模糊词绕过 scope | 宽松候选词 | retrieval |
| 优先级 | 下拉 | P0=100、P1=80、P2=60、P3=40、P4=20、P5=0；新建默认 P3/40 | 保存最近合法档位 | 候选排序 | retrieval |
| 适用范围 | 下拉 | targeted/site/global | 决定下方目标选择器 | 保存 scope | 角色/站点 |
| 指定对象 | 可搜索多选角色 | scope=targeted 时显示 | 保存角色 ID 数组 | 只允许目标角色检索 | Character |
| 指定站点 | 多选站点 | scope=site 时显示 | 保存站点 ID 数组 | 只允许目标站点上下文检索 | Site |
| 全局通用 | 说明状态 | scope=global 时显示 | 不保存目标绑定 | 对全部对象开放候选 | 全局 KB |
| 简介 | 编辑时只读 | 来自已保存摘要 | 当前不能直接修改 | 列表/检索摘要 | KB |
| 知识内容 | textarea，14 行 | 创建时去空白后至少 20 字 | 创建调用 AI 生成摘要与 sections；调用或保存失败必须保留原文并提示，不能声称已保存 | 新建写摘要/片段；编辑按手工正文重建 sections 和绑定 | AI retrieval |

当前服务端允许 targeted/site scope 保存空目标：这种文档会保留对应 scope，但没有任何绑定对象，因而无法正常命中；它不会自动升级为 global。这是当前已知校验缺口，运营保存前必须确认至少选择一个角色或站点，后续应补服务端强制校验。编辑保存会事务性重写 sections 与绑定；AI 生成等待提示不代表一定成功。

### 3.3 知识 AI 生成等待弹窗

状态：`Current`。仅新建知识文档时，在服务端生成简介、目录和知识片段期间显示；编辑已有文档不会进入该弹窗。

| 字段/控件 | 输入/来源 | 用途 | 结果与边界 |
| --- | --- | --- | --- |
| 标题 | 固定 `生成知识文档` | 说明当前任务 | 只读，不代表已经保存 |
| Loading orb / progress bar | 前端动画 | 表示请求仍在等待 | 不是服务端真实百分比，不能当完成度 |
| 状态文字 | 固定说明 | 告知正在生成简介、目录和知识片段 | 不展示内部 prompt、模型或密钥 |
| 预计 1–2 分钟 | 固定估时文案 | 管理预期 | 不是 SLA，超时不自动判定成功或失败 |
| Timer | 前端每 500ms 更新的 `mm:ss` | 展示本次等待时间 | 只计本地弹窗时长，不写数据库 |

该等待弹窗没有取消或关闭按钮；请求成功后关闭并刷新列表，请求失败后关闭并回到表单错误处理。页面动画、估时和计时器均不能替代真实接口结果。

## 4. 状态与失败处理

- 三个页面都必须区分 loading、empty、filter no-match 和 API error。
- Kitshop 刷新、活动商品搜索和知识 AI 处理依赖外部/模型能力，失败不能用旧结果冒充本次成功。
- 商品、活动和知识的站点/角色范围必须由服务端确定性字段控制，不交给模型判断。
- Token、供应商密钥、原始外部响应和内部错误 payload 不在页面字段中展示。
