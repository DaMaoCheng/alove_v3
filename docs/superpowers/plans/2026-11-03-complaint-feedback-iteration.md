# 投诉回复、反馈入口与审核耗时迭代（本地）

## 目标与边界
真实用户投诉按当前意图自然回应，正确保留反馈入口、独立问题及来源限定；减少重复说明和无用审核。复用现有 JEV、反馈历史、审核和单次重写，不改界面样式、不新增模型调用或影响商品、订单、物流、图片和明确人工请求。

## 实现与验收
1. 扩展 `server/jev-commerce-decision-service.js` 现有 `support_followup` 单次判断，增加“已展示入口后继续同一未提交事项”，同步 `product-intent-classifier-service.js` 备用协议及 `chat-feedback-submission-service.js` 规范化，整轮用户证据和同站同角色真实 action 才可采用；不确定、新事项、明确人工及混合问题保留原处理。`chat-feedback-action-service.js` 只在同语种说明已由关联历史消息实际展示时省略重复说明，卡片保留。测游客/注册、首次、新投诉、语种切换、跨角色、空历史、明确人工、订单/商品混合。
2. 同轮说明重叠必须保留首轮可理解的提交指引、原回复事实及语音；先检查现有审核能否同次给出可靠结构化信息，不能用语言关键词剥离句子，失败保留原始回复和入口；必要时收窄范围或记录未通过。
3. `chat-reply-boundary-service.js` 复用已有“明确拒绝且确定可进行一次受限修复时，跳过旧稿语言审核”的逻辑，针对可验证的纯投诉资格扩展，完整新稿复审和失败兜底保持。对主要审核耗时仅依据实际证据优化，不能通过缩短超时或放弃事实、动作校验制造速度提升；不把有限收益说成解决全部延迟。
4. 运行反馈、分流、重写、订单、商品、图片等定向自检；本地独立页面以真实 JEV/生成/审核重放投诉原六轮，逐轮检查同轮/跨轮重复、事实、卡片和耗时，再覆盖普通物流、查单、混合问题。记录真实是否发生重写，不以预设结果冒充真实模型。

## 风险及回退
可能误判对话关系、跨角色/语种错误去重、隐藏新问题入口、模型错误审查及延迟波动。状态必须由本次会话可信来源和当前证据支持，未知走原路径；不修改 env、数据库结构或现有未提交改动。每个受影响文件修改前保存本地备份，失败恢复本次快照；不发布服务器。

## 本地结果（进行中，未通过）
- 现有 JEV 选项加入语义描述及受限的 offered_issue_followup；支持最多 2000 字的整轮证据，站点／用户／角色来源、语言和动作权限保守校验。连续跟进的关联来源存储在服务端 action，接口隐藏；隔离测试和本地事务回滚往返通过。
- 在可信投诉、明确拒绝且确定能进行一次原有修复时，省略已废弃初稿的语言检查；新稿完整审核。新增无本轮反馈卡时的审核约束，并限定投诉答复避免无关诊断。模型漏判风险仍在。
- 真实 JEV 描述正负有限对照：明确同一未提交问题及独立新问题各 4 次符合预期，混合、人工、已提交、换题各 3 次未误选；不能代表所有语种和场景稳定。
- 原投诉六轮真实页面均返回，约 16.7、50.2、81.8、52.1、72.5、24.9 秒；第二轮仍多追问、第三轮机械、第四五轮重复联系说明，未通过。明确同一未提交问题的三轮补测：两轮实际 JEV 选新关系，第三轮真实卡片保留原说明来源且固定后缀未重复；但第二轮无卡且导向不确定的订单页面，第三轮对团队是否收到咨询作无依据判断，整体未通过。
- 此前隔离页面的生成曾发生主、备用均 `empty_answer`；旧记录未保存原始协议结构，不能判定供应商还是解析原因。未更改超时、服务器、env 或 GitHub。
