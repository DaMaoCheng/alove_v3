# 角色人设服务器定点同步方案（2026-09-02）

## 目标与边界

将本地已确认的通用角色与前台角色设定，同步到服务器上“本地和服务器同时存在”的角色。匹配使用稳定 `id`，并同时校验 `slug`、`category_id`、`site_id`，避免把不同角色误配。

本次只写入 `ai_characters.persona_prompt` 与 `ai_characters.speaking_style`。不修改角色名称、头像/封面、开场白、简介、多语言内容、`profile_json`、知识库、站点绑定、可见性、状态或对话数据。服务器独有角色和本地独有角色均不处理。

## 执行步骤

1. 分别从本地和服务器读取非 archived 的通用角色（`fan`、`companion`、`football_babe`、`pundit` 且 `source_type=admin`）及前台角色（`category_id=mascot`）。输出仅包含数量、身份校验结果和字段哈希，不输出人设正文。
2. 计算交集；本轮预期本地 34 个、服务器 32 个、交集 32 个，其中 31 个需要更新，2 个本地独有跳过。
3. 在服务器写入前，将交集角色的旧 `persona_prompt`、`speaking_style` 与身份字段保存到权限为 600 的备份文件。
4. 开启数据库事务。每条更新使用身份条件和“旧字段 SHA-256 哈希”条件；任一角色被他人修改、身份不一致或影响行数不是 1，立即回滚整批。
5. 提交后重新读取全部交集角色，逐条核对本地哈希；确认 `profile_json.style` 未被改动且运行态仍可读取设定字段。
6. 检查服务器服务状态与健康接口；本次不上传代码包、不重启服务、不更新 GitHub。

## 回滚

若回读哈希不一致或运行态检查失败，使用本次备份文件在同样的身份条件下事务性恢复两个字段，并重新核对哈希。备份路径写入更新日志。

## 验收标准

- 服务器交集角色数量与本地一致；服务器独有/本地独有角色未被创建、删除或修改。
- 31 个差异角色的两个设定字段与本地 SHA-256 完全一致；其余字段哈希保持不变。
- 事务无部分提交；旧值哈希冲突时整批 0 写入并明确报错。
- 服务健康检查通过，现有聊天与前台绑定查询不受影响。
- 更新日志记录范围、数量、备份位置、验证结果与未更新 GitHub 的边界。

## 实施结果

- 本地编辑与提示词相关自检全部通过。
- 服务器实际完成 32 个交集角色校验，更新 31 个、跳过 1 个已一致角色；2 个本地独有角色未写入。
- 回读哈希全部一致，健康检查通过；未上传代码、未重启服务、未更新 GitHub。
