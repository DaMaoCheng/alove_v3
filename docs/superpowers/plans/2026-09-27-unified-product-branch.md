# Unified product branch iteration

日期：2026-09-27
状态：本地推进

## 目标

把 JEV 意图判断、商品条件提取、上下文合并、商品搜索、追问、商品气泡和结果回复收敛为一条确定性商品分支。追问最多两轮，条件满足后立即搜索，不修改商品表或消息表结构。

## 复用范围

- 复用 `server/jev-intent-service.js` 的主意图路由和图片优先级。
- 复用 `server/product-intent-service.js` 的多语言条件提取、纠错确认和最近商品上下文。
- 复用 `server/product-search-decision-service.js` 的 readiness/outcome 状态。
- 复用正式账号、游客、Shopify、TTMall 现有商品源和商品气泡持久化。

## 本批次改动

1. 在商品搜索决策层增加追问上限和 `clarification_exhausted` 状态。
2. 从最近已持久化的角色追问回复恢复追问次数，避免新增数据库字段。
3. 正式账号和游客的追问回复写入统一追问标记；游客保留现有角色化 token 机制。
4. 达到上限后只回复一次可执行的替代引导，不再追问，也不发送伪商品气泡。
5. 为明确条件、上下文继承、纠错确认、商品搜索、无结果、源错误、游客/正式账号和两轮上限补充回归自检。

## 不做

- 不重写商品源、商品候选过滤、商品卡片组件或图片分支。
- 不为每种语言增加独立追问流程。
- 不改变商品价格、库存、折扣、结账和站点配置。
- 不修改数据库结构。

## 验收标准

- 明确球队或商品条件时直接搜索并只发送可信商品气泡。
- 条件不足时一次只追问一个最关键字段。
- 用户第一次补充后条件足够，立即搜索，不再追问。
- 连续模糊回答最多追问两次，第三次不再提问。
- 无匹配、商品源错误、客户服务知识问题与条件不足使用不同回复。
- 当前商品的尺码/颜色/替代款问题复用已确认上下文，不重复搜索或追问。
- 游客和正式账号共享同一状态规则，保持既有输出和权限边界。
- 现有素材库、生图、试穿、订单、知识库和商品页面回归通过。

## 回退点

改动集中在商品状态服务、商品回复策略和专项自检；如果验证失败，可以回退本批次文件，不影响商品源配置和历史消息。
