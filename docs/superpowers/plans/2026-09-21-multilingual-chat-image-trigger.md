# 多语种聊天图片触发统一方案

## 目标

让聊天图片请求在不同语种下使用同一套业务决策：普通角色照片请求优先发送素材库图片，素材库没有可用图片时再进入 Venice 生图；用户明确要求生成、试穿或指定上身效果时直接进入生图；商品主图、广告图、白底图、批量图等请求继续被后端拦截。

本阶段只调整图片意图识别和决策编排，不更换素材库、不更换 Venice provider、不修改前端样式和消息展示。

## 当前根因

- `server/chat-image-trigger-service.js` 的确定性规则主要覆盖英语和中文。
- `server/chat-image-intent-classifier-service.js` 的 `AMBIGUOUS_INTENT_HINTS` 仍限制分类器只能处理英语和中文提示词。
- `server/chat-image-generation-service.js` 的游客分支另有一套英语/中文正则判断 `explicitGeneration`，分类器即使识别出其他语种，也可能被这套正则误判为素材库优先。

## 改动范围

### 阶段 1：统一触发结果

- 扩展 `server/chat-image-trigger-service.js` 的结果字段：`intentType`、`explicitGeneration`、`detectionSource`。
- 保留现有确定性安全拦截和图片查看排除规则。
- 将英中规则定位为高置信度快捷路径，不把它们作为全语种能力的唯一入口。

### 阶段 2：多语种分类器入口

- 调整 `server/chat-image-intent-classifier-service.js` 的入口判断，使用通用图片/发送/生成/试穿信号触发分类器。
- 分类器提示词明确要求识别任意语言，并返回统一的 `intentType` 和 `explicitGeneration`。
- 对普通聊天仍不调用分类器；无法判断语言但出现明显图片意图时才走 Venice 兜底。
- 分类器失败时维持现有安全行为：不创建图片任务，不虚假承诺已生成图片。

### 阶段 3：统一素材库与生图优先级

- 修改 `server/chat-image-generation-service.js`，移除游客分支的独立英中 `explicitGeneration` 正则。
- 直接使用统一触发结果决定：素材库优先、直接生图或拒绝。
- 保留游客额度、生成中锁、重复请求幂等和失败不扣额度逻辑。

### 阶段 4：可观测性与自检

- 为触发结果保留检测来源和意图类型，供现有 provider 调用日志和图片任务日志关联排查。
- 扩充现有图片触发与分类器自检，不新增重复的业务服务。
- 覆盖英语、中文、西班牙语、葡萄牙语、法语、德语、日语，以及未知语种样例。

## 不做范围

- 不修改 Venice API 地址、模型或密钥。
- 不修改素材库图片选择算法。
- 不修改图片额度、生成任务状态机和前端渲染。
- 不为每条普通聊天强制调用分类器。
- 不把语言列表扩展成维护成本高的关键词表作为唯一方案。

## 验收标准

1. 同一语义换用不同语言后，业务决策一致。
2. 普通照片请求：先尝试角色素材库，素材库没有图片时才创建生图任务。
3. 明确生图、试穿或指定上身效果：跳过素材库，直接创建生图任务。
4. 商品主图、白底图、广告图、批量图、图片查看请求不创建生图任务。
5. Venice 分类器失败或超时不影响普通聊天，不产生图片任务，也不声称图片已生成。
6. 游客额度、生成中锁、幂等、失败不扣额度保持原行为。
7. 现有图片触发、分类器、游客生图、最终回归自检全部通过，`npm run check:deployment` 通过。
8. 真实本地链路至少验证：素材库命中、素材库耗尽转生图、明确生图直达、禁止请求拦截、跨语种触发。

## 回退点

本次改动集中在触发结果和游客编排两个服务；若回归失败，可整体回退本阶段提交，不涉及数据库结构、配置和前端资源。
