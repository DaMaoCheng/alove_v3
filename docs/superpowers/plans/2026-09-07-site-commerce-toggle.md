# 站点购买入口开关迭代方案

## 目标

在站点管理中增加站点级 `commerce_enabled` 开关。默认开启，保持现有站点行为不变；关闭后保留商品搜索、展示和商品详情 URL，仅将商品详情主按钮改为 `View more` 并阻止服务端加购/结算写操作。

## 实施范围

1. 数据层：`sites.commerce_enabled`，迁移默认 `1`，新建站点默认开启。
2. 管理端：站点编辑弹窗增加购买入口开关，读写同一字段。
3. 公共站点/商品数据：搜索、Kitshop、聊天商品消息和站点 branding 暴露 `commerceEnabled`，旧数据缺字段按开启兼容。
4. 前端详情面板：关闭时隐藏尺码/支付/定制购买操作，主按钮显示 `View more`，点击打开商品 URL；无 URL 时保持禁用并显示既有详情入口。
5. 服务端防线：Shopify、TTMall 的非空加购和结算入口检查开关，返回明确的 `SITE_COMMERCE_DISABLED`，不清空已有购物车、不影响订单读取和站点商品刷新。

## 不做

- 不修改角色人设、商品源抓取、订单读取、支付合同或现有样式体系。
- 不删除已有购物车数据，不为平台新增平行实现。

## 验收标准

- 缺少迁移字段或旧商品快照时行为仍等同开启。
- 管理端开关保存后刷新仍保持状态，并只影响当前站点。
- 关闭站点的聊天、搜索、Kitshop详情均显示 `View more`，准确跳转到商品 URL。
- 关闭站点不会显示可操作的尺码、支付或加购流程；缺少 URL 不产生错误跳转。
- Shopify/TTMall 直接调用非空加购和结算接口均被服务端拒绝；订单历史、商品检索和其他站点不受影响。
- 通过语法检查、专项自检、服务健康检查和浏览器真实点击验证。

## 回退点

将 `commerce_enabled` 恢复为 `1` 即可恢复购买入口；代码字段保留不影响旧数据。
