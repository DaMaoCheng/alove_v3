# 商品跟进与最近 IP 记录实施方案

## 目标

修复商品对话中的短追问不能继续匹配真实商品、请求当前商品图片却被错误回复的问题；同时为正式账号和游客会话记录并仅在管理员详情中展示最近一次 IP 与中文国家/地区名。

## 批次 1：商品上下文延续与商品卡图片

### 修改范围

- `server/product-intent-service.js`
  - 将颜色、尺码等短商品追问识别为对最近已确认商品条件的补充，不再把它当普通闲聊。
  - 保持当前的站点、球队、商品类别和受众过滤，不允许跨站或跨队猜测。
- `server/chat-product-recommendation-service.js`
- `server/guest-chat-product-service.js`
  - 复用相同的意图结构；当用户在已有、已验证商品上下文中请求商品图片时，复用该商品卡及其可信图片，而不是请求角色生图或让模型自由回答。
- 相应自检脚本
  - 覆盖“England jersey → white color”会继续走确定性商品检索。
  - 覆盖“已确认商品 → 请求图片”只复用商品卡，不创建角色图片任务。

### 不做

- 不生成电商白底图、广告图或伪造商品图。
- 不把商品图片请求改成角色自拍/生图。
- 不改变折扣、结账或商品详情逻辑。

### 验收

- 搜索结果为空时只走受控澄清，不捏造商品。
- 白色等追问只返回同站点、同队且符合颜色的商品卡。
- 商品图片请求可展示当前可信商品卡；无可信商品时走简短澄清。
- 游客与登录用户都使用同一套商品意图规则。

## 批次 2：最近 IP 与后台详情展示

### 数据模型

- `users` 与 `guest_sessions` 各新增：
  - `last_ip`：最近一次可信客户端 IP。
  - `last_ip_region`：中文国家/地区名。
  - `last_ip_at`：记录更新时间。
- 迁移通过项目既有 `addColumnIfMissing` 实现，空库和已有库均可重复执行。

### 数据来源与隐私边界

- 复用已有 `getRequestIp(req)`：只信任受配置保护的代理头；不直接信任任意客户端伪造的 `X-Forwarded-For`。
- 优先读取 Cloudflare 国家代码，使用本地 `Intl.DisplayNames('zh-CN')` 转中文名；本地/未知来源显示“未知地区”，不调用第三方 IP 查询服务。
- 只保留最后一次值；不建立访问历史、画像或普通用户可见接口。

### 写入时机

- 正式账号：注册、登录、以及已认证 API 请求时更新。
- 游客：创建/恢复游客会话及发送对话时更新。
- 使用短时间节流，避免同一 IP 的高频请求造成无意义数据库写入；IP 或地区变化会立即更新。

### 后台展示

- 保持当前表格排版不变。
- 在“账号管理”和“游客会话”的展开详情“基础信息”中增加：`最近 IP`、`最近访问时间`。
- 显示格式：`中国 · 203.0.113.10`；无可用数据时显示 `-`。

### 验收

- 账号、游客分别写入与读取最近 IP；管理员列表接口返回需要的字段，普通用户接口不返回。
- 可信代理、本地 IP、缺失地区头及空值均有确定行为。
- 账号与游客详情 UI 保持原表格/展开样式。
- 数据库自检、商品自检、后台游客会话自检及真实本地接口链路通过。

## 回退

- 新字段均可为空；关闭或回退代码不会影响现有认证、游客会话或商品卡。
- 如发生异常，只停止写入/展示逻辑，不删除历史会话、账号和商品消息。
