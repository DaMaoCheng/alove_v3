# 正式账号聊天生图三日窗口额度

## 目标

将正式账号的聊天生图额度从“每个角色每天 100 张”调整为“同一个账号的全部角色共享额度，首张图片成功完成后开启 3 天窗口，窗口内最多成功生成 10 张”。游客图片资格保持现有一次性 entitlement 规则不变。

## 代码落点

- `server/chat-image-quota-service.js`
  - 增加 3 天窗口和 10 张上限常量。
  - 增加窗口状态查询与成功图片计数方法。
  - 只有图片进入 `ready` 并写入 usage 后才更新窗口。
- `server/chat-image-job-service.js`
  - 继续复用成功后记录 usage 的入口，不改变游客 entitlement 消耗流程。
- `server/db-bootstrap-chat-tables.js`
  - 新增 `chat_image_quota_windows` 表，支持已有环境启动时自动创建。
- `database/schema.sql`
  - 同步数据库快照。
- `scripts/chat-image-quota-lock-self-check.mjs`
  - 验证首张成功启动窗口、10 张封顶、窗口过期后重新开放。

## 数据规则

窗口主键为 `internal_uid`，账号下所有角色共享 `window_started_at` 和 `image_count`。

- 没有窗口：允许生成；首张成功后写入起点和计数 1。
- 窗口未过期且计数小于 10：允许生成。
- 窗口未过期且计数达到 10：拒绝生图，只走额度提示。
- 窗口达到 3 天：下一张成功图片开启新窗口，计数重置为 1。
- failed、cancelled 不计入成功计数；queued、generating 不计入成功计数，但会在同一账号的额度锁内预留名额，防止并发请求绕过 10 张上限。
- 游客不写入该表，继续使用 `guest_image_entitlements`。

## 不做范围

- 不修改游客额度、游客注册引导或素材库优先级。
- 不修改生图 provider、图片任务状态机和前端样式。
- 不删除历史 `chat_image_usage` 记录；窗口表从本次规则生效后的成功图片开始建立。

## 验收标准

1. 正式账号第一张图片成功完成后，窗口起点等于该图片完成并记录 usage 的时间。
2. 同一账号在 3 天内第 10 张成功图片后，第 11 张不创建任务。
3. 不同角色和不同会话共享额度；切换角色不能绕过限制。
4. 3 天窗口过期后，下一张成功图片开启新窗口。
5. 失败、超时、取消不增加计数；游客原有一次性资格行为不变。
6. 图片素材库命中不消耗正式账号生图窗口额度。
7. 图片额度、任务锁、最终回归、部署检查和本地 HTTP smoke 全部通过；测试夹具不能留下可被本地 worker 复活的旧任务。

## 回退点

改动集中在额度服务、成功 usage 记录和数据库初始化；若回归失败，可回退本阶段提交，不影响图片 provider、素材库和游客 entitlement 表。
