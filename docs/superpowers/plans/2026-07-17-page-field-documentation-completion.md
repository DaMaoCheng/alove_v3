# 页面与字段设计文档补齐计划

日期：2026-07-17
状态：已完成
范围：仅文档，不修改页面、接口、数据库或运行配置

## 目标

把现有 `docs/DESIGN.md`、`docs/design/` 与 `docs/system/pages/` 补齐为可持续维护的产品文档体系，使新成员或后续 Agent 能从页面入口找到：页面目标、适用身份、所有字段/控件、输入方法、校验、数据来源、操作结果、关联业务对象和长期产品规则。

## 分批范围

### 批次 1：页面索引与统一模板

- 核对前台路由、后台 `view`、隐藏入口、弹窗和页面级面板。
- 在页面索引中建立完整页面清单和统一字段表列。
- 验收：当前代码中的用户路由和后台导航均能在页面索引中找到唯一文档入口。

### 批次 2：用户侧页面

- 补齐登录、注册、忘记密码、App Shell、Discover、角色确认、Search、404、Chat、商品详情、实时通话、Create、头像生成、Profile、Invite、Kitshop、反馈和 Creator Workspace。
- 验收：每个页面都有状态、目标、入口/身份、字段/控件、操作结果、状态与权限边界；游客和正式账号差异明确。

### 批次 3：后台页面

- 补齐概览、角色、站点、前台、轮播、Kitshop、广告活动、知识库、反馈、账号/游客、错误日志及占位/隐藏入口。
- 验收：所有列表列、筛选器、表单字段、弹窗字段、批量操作和状态流转均有说明；敏感字段只记录输入与处理边界。

### 批次 4：长期规则一致性

- 对照已发布行为校正 `docs/design/` 中过期或冲突的 `Current` 描述。
- 给页面文档补充长期规则和系统文档交叉引用。
- 验收：手动广告/自动主动消息、游客开关和其他近期能力不再出现状态冲突。

### 批次 5：文档验收

- 运行 `node scripts/system-docs-self-check.mjs`。
- 检查 Markdown 相对链接、状态标记、页面覆盖、字段表结构和未确认项。
- 对照代码做多 Agent 交叉审查；不能确认的内容标为 `TBD` 或缺口，不写成 `Current`。
- 验收：无断链；所有当前页面有唯一入口；占位/隐藏能力不会被误写成已可用；本轮不产生业务行为变化。

## 修改边界

- 长期产品规则继续由 `docs/design/` 维护。
- 页面、弹窗、字段和控件事实继续由 `docs/system/pages/` 维护，不在两处重复整表。
- API、数据表、服务和部署命令继续留在 `docs/system/`；页面文档只做必要链接。
- 本轮不更新服务器；是否提交 GitHub 由用户在本地验收后决定。

## 风险与处理

- **代码与文档不一致**：以当前模板、controller/service 和服务端校验为准，历史文档只作线索。
- **动态配置被写死**：站点、商品、角色、活动等只记录来源和过滤规则；运行配置注明核对时间。
- **多 Agent 格式漂移**：所有页面使用页面索引定义的统一字段列，由主 Agent 最终整合和审查。
- **把未来方向误写成现状**：必须使用 `Current`、`Approved direction`、`TBD`、`Placeholder`、`Hidden` 区分。

- 多 Agent 只读审查及最终真实路由、表单、dialog 反查发现的事实偏差与漏项已回写；未通过文档修改掩盖现有业务缺口。
