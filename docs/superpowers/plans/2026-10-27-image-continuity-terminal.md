# 图片穿搭承接与终态补句：本地续修

本轮只本地修改、验证，不发布。保留上一轮未提交修改。新检查点和数据库快照在本地私有备份目录。

## 范围与验收

1. 穿搭承接：复用当前图片分类的一次请求，条件传入最近有界 USER 描述，并单独输出前述是否为角色衣着、继续/换造型/不确定及原文证据。小型 appearance-context helper 校验用户证据和媒体边界；没有当前图片许可绝不提升权限。已交付普通续图继续原规则，不继承裸露；不确定时先澄清，不读图库或占配额。商品试穿继续同站商品图与确认保护，无新的语言词表或会话状态系统。
2. 终态补句：扩展既有失败回复队列为同一终态通道，保留旧 jobType/导出兼容。图片资产私有上下文记录初稿关联、状态、生成/审核开始、缓存稿、完成标记；模型调用前消费一次额度，不因重启/重复job/旧job清理重置。图片完成和初稿落库两入口以资产行串行汇合；只对已落初稿仍待完成的图补一句，已自然终态、后续新用户回合跳过。保留混合问题原文，不重做商品/物流答复，不把子任务目的伪装成模型分类许可。
3. 模糊图：只核查与必要诊断，不关闭供应商安全模式、不改模型或原请求内容。官方响应头与本地请求参数用于解释原因，不能从一个 header 推断具体触发文字或实际计费。供应商明确模糊结果与网络错误分型；明确结果不盲重发，网络/5xx仍保留原有限重试。供应商调用前保留实际提示与最少白名单诊断，不记录凭证/余额/任意响应头。

涉及现有 image classifier/generation/context、failure-reply job、image job、主回复持久化、status/boundary 和日志；新增小型上下文校验helper及专项，不新增数据库结构、模型、视觉样式/CSS或平行队列。

## 验证门槛

- 先跑原入口红例，再修复并检查普通图库、已交付续图、状态查询、无图片请求、换装/裸露、商品参考图、混合问答与旧失败回复。
- 终态检查两个完成顺序、并发 enqueue/handler、重启在生成/审核前后、租约/owner改变、新用户回合、job清理后重放；每资产最多一轮补句生成、一轮既有审核（含语言审核和原有限备用链），不得跨任务重新调用。
- 双连接验证锁序与真实 schema；数据库专项串行，自有fixture单独备份清理，五运营/知识表hash保持。
- 本地真实页面：普通图库不改为无谓生成；含糊索图正确承接或澄清；明确同一造型真实生成并逐图检查；图片完成后自然补句；混合业务答案保留；同一图片重放不新增消息或模型调用。隔离通过不替代真实模型/页面。
- 实际失败和供应商结果保留，不用后续成功覆盖。测试后恢复标准4173服务，验证PID/cwd/health。


## 实跑后补齐的必要边界

- 终态补句不把原混合问句再次作为当前用户命令：保留原persona/language/safety层，历史和原请求作为只读来源，最后system明确caption任务；仅可信属主当前终态anchor选择caption contract，不制造image-only分类许可。生成与审核同一范围，普通混合问题仍要求完整业务答复。
- 仅终态worker复用游客sanitize安全过滤，不复用会按原问题重分流的normalize；保留优惠码等安全规则，防止图片+优惠/跟踪混合问题的补句被替换成业务提示。仅caption去舞台标记，审前审后同文；空稿有限兜底，不加调用。
- 保留实际生成provider/model/baseUrl，审核识别真实备用模型；私有asset账本先消费阶段再调用、事务提交文字/完成标志。asset-first入队不再锁消息尾，登记与付费阶段统一session→job→asset→消息尾锁序。
- 复用现有消息查询与前端图片轮询，公开terminalReplyPending布尔、兼容失败旧flag；ready等待补句期间不停止，完成即停止。render恢复钩子识别ready/failed+pending，覆盖图片先完成而主回复后登记的竞态。无UI/CSS变动。
- 图库正文伪造的{image:...}/{photo:...}控制占位符，仅在真实本回合图片锚点且用户未要求该语法时清理；正文与混合业务答案保留，审查清理后的同文。
