# 可信商品目录一致性规格

日期：2026-07-15
状态：Implemented and verified locally

## 目标

- Alove 内部的 Kitshop、商品搜索、聊天推荐、游客商品卡、广告活动选品和商品详情刷新，统一读取当前站点配置的可信商品源。
- Shopify 站点使用已配置的只读 Admin API 读取商品事实；独立站主题是否对未登录访客隐藏某个楼层或商品，不影响 Alove 展示该商品。
- 保持真正不可售或未发布商品的排除边界，不把 Draft、Archived 或没有 Online Store URL 的商品暴露给前台。

## 统一商品可见规则

Shopify 商品必须同时满足：

1. `status = ACTIVE`；
2. `onlineStoreUrl` 非空；
3. 商品能够被当前站点绑定的可信商品源正常读取并归一化。

独立站主题中的登录判断、Liquid `customer` 条件、首页楼层显隐或访客搜索显隐，不参与 Alove 商品可见性判断。

## 链路规则

### Kitshop

- 继续读取 Shopify Admin 商品、主主题首页栏目和销量快照。
- 不改变两层货架、缓存、去重、销量混排或刷新规则。

### 广告活动选品

- 按当前站点查询可信商品源。
- 使用统一 50 个候选池完成名称/SKU 匹配，再最多返回 8 个结果。
- 不能因为通用商品源默认 5 条而截断后台选品候选。
- 后台输入是确定性查找条件，必须保留名称或 SKU 原文，不得经过面向聊天的语义改写；从 Kitshop 复制完整商品标题时必须能命中同站点对应商品。
- Shopify Admin 多词标题使用完整短语查询；单词标题和 SKU 只能使用平台支持的前缀通配符，不能截断完整标题或生成前置通配符查询。

### 搜索、聊天与游客商品卡

- 继续使用站点可信商品源和现有确定性筛选。
- 不改变各入口最终展示数量、游客优惠剥离、活动优先级或商品去重规则。

### 商品详情与结账解析

- 使用站点绑定的可信商品源刷新价格、库存、尺码、variant ID 和购物车链接。
- Shopify Admin 商品源不得在 resolve 阶段降级为未登录公共 storefront 搜索。
- 找不到匹配商品或第三方读取失败时继续保留消息/货架中的原商品快照，不能用其他商品覆盖。

## 安全边界

- Admin Token 只在服务端解密和使用，不进入 URL、响应、日志或前端状态。
- 前台接口只能按已解析的 active 站点读取；游客继续执行站点开关、Origin、网络额度和字段清洗。
- 普通正式账号只能读取 active 的账号所属站点；管理员保留跨站运营能力。所有商品入口严格解析显式站点，不允许无效/停用 slug 回退默认站。正式账号按“账号 + 站点”执行独立商品请求额度和同时在途请求上限。
- Search、Resolve、Kitshop 和聊天商品消息均不向客户端返回服务端匹配用的 `sourceItem` 或 Shopify 精确 `inventoryQuantity`；新商品消息在持久化前即清洗，旧历史消息在读取时清洗，是否可选只使用现有公开可售状态。
- 商品源继续只读，不调用 Shopify mutation。
- 商品匹配仍要求稳定商品身份，不允许相似但不同的商品覆盖历史快照。

## 非目标

- 不展示 Draft、Archived 或未发布到 Online Store 的商品。
- 不绕过独立站登录完成购买，也不复制独立站登录态。
- 不修改 Kitshop UI、商品卡 UI、广告活动 UI 或 Shopify 店铺主题。
- 不新增商品导入、人工商品编辑或全量商品管理页面。

## 验收标准

- 广告选品请求 8 条时，后台从 50 个可信候选中筛选，而不是只读取 5 条。
- 粘贴 Kitshop 完整商品标题时，广告选品返回对应可信商品；完整标题的关键原词不会被聊天同义词替换。
- 主题层对游客隐藏、但 `ACTIVE` 且有 `onlineStoreUrl` 的商品可以被广告选品、搜索、聊天和 resolve 使用。
- resolve 使用 Shopify Admin endpoint 和服务端 Token；不会请求公共 `/search`、`/search/suggest.json` 或商品公开 JSON 作为 Admin 站点的主链路。
- Draft、Archived、`onlineStoreUrl = null` 商品继续被排除。
- 错误、空结果和身份不匹配时保留原商品快照。
- 商品源、搜索、详情刷新、聊天、游客、广告活动和 Kitshop 回归通过。
- 无 Origin 的游客商品请求、普通账号跨站/停用站请求和超额或突发正式账号请求分别得到确定性 `403` / `429`，且不会进入可信商品源读取。
