# 前台手动广告投放功能规格

## 目标

- 管理员可在“前台管理”中为一个已绑定前台的站点选择当前有效广告活动并立即启动投放。
- 投放由该站点前台角色发送活动文本、商品消息和角色语音，并记录真实成功/失败数量。
- 弹窗只展示活动选择、已处理/总数、成功数和失败数，沿用当前确认的 UI。

## 非目标

- 不新增活动编辑字段，不改变广告活动创建页面。
- 不绕过活动去重、站点、角色范围或时间校验。
- 不向游客、停用账号、跨站账号、未激活前台或没有正式前台会话的账号投放。
- 不在本功能中新增定时投放、取消任务、重试按钮或逐用户明细页面。

## 确定性规则

1. 下拉菜单只返回当前站点、`active`、已开始且未过期、角色范围为 `all` 或 `mascot` 的活动。
2. 点击发送时服务端再次校验活动，不能信任前端传入的站点、角色、人数或活动状态。
3. 目标用户必须同时满足：账号为 `active`、归属当前站点、已激活当前站点前台、存在该前台的正式活跃会话。
4. 同一活动对同一账号只允许成功投放一次；同一站点同一活动同时只允许一个进行中的手动投放任务。
5. 管理员手动广告不检查、不占用自动主动消息的每日额度，也不受“上一条主动消息未回复”门禁影响；自动主动消息和自动活动匹配继续使用原额度规则。
6. 成功以活动文本和商品消息均已保存、活动 delivery 已完成为准；手动发送不创建主动消息 delivery。
7. 投放任务与逐用户结果必须持久化。进程中断后，运行中的批次可恢复，不能重复成功投放。

## 状态

- 投放任务：`queued -> sending -> completed | failed`。
- 逐用户目标：`queued -> sending -> sent | failed`。
- 弹窗：`ready -> sending -> completed`；接口错误保留在当前弹窗内并允许重新提交。

## 权限

- 读取活动和进度需要管理员身份。
- 启动投放需要 `admin:promotions:write`。

## 验收标准

- 跨站、草稿、暂停、未开始、已过期、非前台角色活动不能出现在下拉菜单，也不能通过直接请求启动。
- 重复点击、刷新页面、worker 重启和任务重放不会重复生成活动消息。
- 真实进度满足 `processed = sent + failed`，完成时 `processed = total`。
- 原有自动主动消息、广告匹配、活动编辑、前台编辑和后台列表不受影响。
