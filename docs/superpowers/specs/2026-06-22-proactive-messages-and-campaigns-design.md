# Proactive Messages And Promotion Campaigns Design

## Goal

把“角色主动发消息”和“促销活动投放”拆成两个独立层：

1. 主动消息调度层：决定什么时候发。
2. 广告活动层：决定发什么促销内容。

这样后续继续扩展广告管理、商品关联、投放统计时，不会把现有聊天主动消息链路重新揉成一团。

## Scope Split

### Phase 1：主动消息调度器

- 只解决站内会话的主动触达时机。
- 只覆盖 `mascot` 和 `creator`。
- 复用现有 `SEND_PROACTIVE_MESSAGE` job 和消息落库。
- 不引入广告活动后台。

### Phase 2：广告活动管理 + 命中投放

- 新增管理员“广告活动”页面。
- 允许按站点、角色范围、时间窗口、关键词、优先级配置活动。
- 在主动消息真正发送前，先做活动匹配。
- 一个账号同一活动只投放一次，不因多个角色重复触达。

## Deterministic Rules

- 活动命中必须是确定性规则，不交给模型自由判断。
- 同站点优先。
- 仅匹配 `active` 状态且在时间窗口内的活动。
- 角色范围只支持 `all`、`mascot`、`creator`。
- 关键词只基于最近消息文本做简单命中评分。
- 同分时按：分数高优先、优先级数字小优先、结束时间更早优先、创建更早优先、ID 字典序优先。

## Delivery Guard

- 同一账号命中同一活动，只允许发一次。
- 去重维度是账号 `internal_uid`，不是 session，也不是 character。
- 活动投放记录和旧 `mascot_ad_deliveries` 分开存，避免老表语义继续膨胀。

## Admin UI Phase 2 Baseline

第一版后台只做最小可用：

- 手填活动标题
- 站点
- 角色范围
- 商品标题
- 商品 ID
- 商品链接
- 关键词
- 优先级
- 生效时间
- 主动发送文案
- 状态

第一版先不做：

- 商品搜索器
- 商品卡片预览
- 投放统计看板
- 多活动冲突可视化

## Notes

- 第一版广告活动发送仍是纯文本主动消息，不自动塞商品气泡。
- 后续如果要把活动和商品气泡联动，再单独补一层商品素材组装，不挤进本次实现。
