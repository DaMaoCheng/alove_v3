# 站点前台语言维护说明

## 唯一入口

用户侧固定界面文案统一维护在 `src/i18n/site-copy.js`。页面只能通过 `createSiteCopy(siteLanguage)` 读取文案，不要在页面里新增 `if Chinese else English`，也不要创建第二份页面或第二套翻译模块。

站点的 `default_language` 决定用户首次进入该站点路径时的固定界面语言。这里的“固定界面”包含导航、登录注册、发现、搜索、聊天控件、创建角色、个人资料、反馈、商品详情、通话状态、图片生成状态、确认弹窗和可预期的用户侧错误提示。异步任务即使保存了旧语言状态文本，用户端也必须按当前页面语言通过本语言包显示确定性状态，不能直接把数据库状态文案当作界面翻译。

以下内容不由语言包翻译：

- 后台管理控制台；
- 创作者工作台和网红运营内容；
- 商品标题、商品描述、角色名称、管理员或用户填写的人设、开场白等业务数据；
- 后台配置的首页轮播标题、正文、按钮，以及站点运营自行录入的活动文案；这些内容应由运营按目标站点语言直接填写；
- 用户输入、模型回复和其他用户生成内容。

固定产品分类、导航名称等系统枚举仍属于界面文案：界面显示时翻译，但接口请求、筛选和数据库仍使用稳定的原始 `id` / `label`，避免切换语言后破坏业务匹配。

低层复用组件可以保留 English 作为无 copy 参数时的兼容兜底，但所有用户侧页面调用都必须显式传入当前站点的 copy；不能把兼容兜底当成页面语言实现。

## 角色默认语言

- 管理员创建或管理的角色：新会话优先使用可信站点的 `default_language`。角色人设本身不会被翻译，只会把本次会话的输出语言设为站点语言。
- 用户自行创建的角色：新会话优先保留创建角色时选择的语言，不会被所在站点覆盖。
- 用户已有的角色激活语言偏好优先级最高。
- 已经存在的会话保存自己的语言，不会因为管理员修改站点语言而被静默改写。
- 用户在聊天中明确要求切换语言时，仍按现有会话语言切换规则处理。

## 新增语言步骤

1. 在共享语言库中确认该语言存在，并有稳定的语言代码。
2. 在 `site-copy.js` 新增完整语言包，键名必须与英文源语言包完全一致。
3. 把语言包注册到 `SITE_COPY_BUNDLES`。
4. 不翻译动态业务数据，不修改后台或创作者工作台。
5. 运行 `node scripts/site-language-copy-coverage-self-check.mjs`，它会检查语言包键集合、空值、前台静态引用和关键页面接线。
6. 分别用英文站点和目标语言站点验证登录注册、发现、搜索、聊天、创建、资料、反馈、商品、通话及所有弹窗/错误状态。

任何新增用户侧页面、弹窗或错误文案，都必须先在英文源语言包定义键，再为所有已注册语言补齐对应值；覆盖检查通过后才能交付。
